# 08. 이행 계획

## 1. 원칙

1. **기능을 깎지 않는다.** 범위 축소는 CM 결정 사항이다.
2. **동등성은 증명한다.** 기존 시스템과 기계적으로 대조한다.
3. 단계마다 **동작하는 것**을 만든다. 통합을 뒤로 미루지 않는다.

## 2. 단계

| 단계 | 내용 | 산출물 |
|---|---|---|
| **0 · 기준선** | 기존 OpenAPI 스냅샷, 화면 요소 체크리스트, 섀도 환경 | `baseline/` |
| **1 · 데이터** | 스키마 설계·적용, 기존 DB → 신규 ETL, 전수 검증 | `db/migrations/` |
| **2 · 골격** | 모노레포, 계약, API 골격(인증·권한 36리프·감사·캐시·큐), 셸 레이아웃 + 메뉴 9개 | `packages/*` |
| **3 · 조회** | TDB 조회 + 상세 + **PDF 뷰어 이식** | 화면 1·11·14 |
| **4 · 워크플로** | TDB 반입·검수 + TDB 관리 (API 48개 — 최대 덩어리) | 화면 2·3 |
| **5 · 반출** | TDB 반출이력 | 화면 4 |
| **6 · MDB** | MDB 조회 + MDB 관리 + Tag 이력 (API 51개) | 화면 5·6·12 |
| **7 · 운영** | 시스템 로그 + 사용자·권한 + 백업 + 도움말 | 화면 7·8·9·10·13 |
| **8 · 전환** | 섀도 비교, 성능 튜닝, 병행 운영, 전환 | — |

> 단계 4가 전체 리스크의 절반이다. 선행 설계에 충분히 시간을 쓴다.

## 3. 동등성 검증 — 3중

### ① API 계약 스냅샷
기존 FastAPI에서 OpenAPI를 1회 추출해 기준선으로 고정한다.

```bash
# 기존 서버에서 1회: main.py 의 openapi_url=None 을 잠시 해제하고
curl -s http://127.0.0.1:8000/openapi.json > baseline/openapi.json
```
신규 서버는 201개 엔드포인트가 이 스냅샷의 경로·파라미터·응답 형태를 만족하는지
테스트로 대조한다.

### ② 화면 요소 체크리스트
기존 HTML 14개에서 `id`·버튼·라벨을 추출해 체크리스트를 만든다
(`docs/05-기능인벤토리.md` 3절이 그 초안이다).
Vue 구현 후 Playwright로 **같은 라벨이 전부 존재하는지** 기계적으로 대조한다.

### ③ 섀도 비교 (2주)
신·구 서버를 같은 DB 스냅샷에 붙이고 주요 조회 API를 양쪽에 동시 호출해
**응답 JSON을 diff** 한다. 쓰기 작업(반출·승인)은 구 시스템에서만 수행한다.

## 4. 데이터 이행

| 단계 | 내용 |
|---|---|
| 1 | 기존 DB 스냅샷 확보 (`pg_dump`) |
| 2 | `documents.source_path` 문자열 → `folders` 트리로 분해 |
| 3 | 파일을 sha256 계산하여 `blobs/` 로 재배치, `files` 재작성 |
| 4 | 나머지 테이블 1:1 이행 |
| 5 | **전수 검증**: 건수, sha256 합계, 폴더 경로 재구성 결과가 원본과 일치하는지 |
| 6 | 리허설 → 본 이행 → 검증 → (실패 시) 롤백 |

검증 쿼리는 `db/verify/` 에 둔다. **수동 눈 검사로 대체하지 않는다.**

## 7. 진행 기록

### 2026-10-25 — 단계 1·2 완료

**적용한 것**
- 설계문서 10편 (`docs/`)
- 모노레포: `contracts` / `api` / `web` + `db` + `deploy`
- DB 스키마 적용 (jin114.co.kr:31015 / `ghub_tdms`) — 테이블 29, 인덱스 93, 감사 월 파티션
- 계약 패키지: 권한 리프 36개, 메뉴 9개, 공통·인증·폴더·자료 스키마
- API: Fastify 5 + 선언형 권한·감사 + 기동 시 검증 + LISTEN/NOTIFY 캐시 + 세션
- 화면: 로그인 / 최초 비밀번호 변경(미루기) / TDB 조회 / 접근 불가 안내 + 나머지 11화면 라우트 골격
- 검증: 52,000건 적재 후 전 쿼리 10ms 미만, 테스트 13개 통과, 번들 62KB gzip

**검증 중 발견하고 고친 결함 2건**

| # | 내용 | 조치 |
|---|---|---|
| 1 | `ix_documents_browse` 가 `folder_id` 선두라 목록 **1페이지**에서 쓰이지 않음 → Seq Scan + 정렬로 51ms | 정렬키 선두 짝 인덱스 추가 (`0008`). **51ms → 0.2ms** |
| 2 | `z.coerce.boolean()` 이 문자열 `"false"` 를 `true` 로 읽어 **Isometric 토글이 무력화**됨 (전체 도면의 63%를 가르는 필터) | `BoolParam` 전용 파서 추가, 회귀 테스트 4건 |

둘 다 **실제 규모(52,000건)로 돌려 보기 전에는 드러나지 않았다.**
소량 샘플로는 플래너가 다른 선택을 하고, 기본값만 쓰면 토글 버그가 보이지 않는다.
→ 이후 단계에서도 **각 화면을 실데이터 규모로 한 번씩 돌려 보는 것**을 완료 조건에 넣는다.

**실행 검증을 못 한 것 (정직한 기록)**

`packages/worker` 의 Python 코드는 작성했으나 **이 개발 장비에서 실행하지 못했다** —
`python3-venv`/`pip` 가 없고 설치 권한이 없다. 대신 워커가 쓰는 것과 **같은 SQL** 로
큐 계약을 검증하는 스모크 테스트를 만들었다(`db/tools/queue-smoke.mjs`, 6종 통과).

워커를 실제로 돌리려면:

```bash
sudo apt install python3.12-venv
cd packages/worker && python3 -m venv .venv && .venv/bin/pip install -e .
.venv/bin/python -m tdms_worker --id 1
```

엑셀 내보내기 핸들러(`handlers/excel.py`)의 실제 산출물은 아직 확인하지 못했다.
워커를 띄운 뒤 가장 먼저 검증할 항목이다.

### 2026-10-25 — 단계 4 전반 완료 (반입·검수)

**적용한 것**
- 리비전 상태 머신을 **순수 함수로 분리** (`@tdms/contracts/revision`) — DB·파일시스템을
  모르므로 전수 테스트가 가능하다. 단위 테스트 28건
- 반입 등록: 개별 자료(multipart), Zip 대량(워커 작업으로 넘김)
- 검수 대기: 세트 단위 목록, 선택 승인·반려(권한 분리), 일괄 처리 시 실패 건 개별 보고
- 확인 필요: 목록 + 재검수 / 경로 재선택 / 반려
- 중복반출 현황, 병합본 첨부 후 승인
- 화면: 반입등록 / 검수 대기 / 확인 필요 3개 탭 + 모달 3종

**승계한 규칙 (기존 CM 확정 사항)**

| 규칙 | 구현 |
|---|---|
| 리비전 정수는 승인돼야만 오른다 | `determineRevBranch` — 반려는 정수를 소모하지 않는다 |
| 반려는 글자(a·b·c)로 이력에 남는다 | `rejectLetter` |
| 중복반출이면 분기로 나눈다 | 서로 다른 업체 미반납 수정용 2건 이상 → 분기 a |
| 분기본은 승인해도 현재본이 되지 않는다 | `approveOutcome` → `MERGE_REQUIRED` |
| 시스템은 도면을 자동 병합하지 않는다 | 사람이 CAD 로 통합한 파일만 정식 Rev 로 승인 |
| 반출이 전부 돌아오기 전엔 분기 승인 불가 | `branchApprovalBlocked` |
| 반려하면 그 반출은 다시 미반납이 된다 | `reopenDistributions` |
| 어떤 경우에도 행을 지우지 않는다 (D-6) | 상태만 바꾼다 (REJECTED / MERGED) |
| 잠금 순서는 언제나 '자료 먼저' | 파일부터 잠그면 같은 세트를 서로 쥐고 교착 |

**검증 결과**

| 항목 | 결과 |
|---|---|
| 상태 머신 단위 테스트 | 28건 통과 (A·B 동시 수정 전체 시나리오 포함) |
| 전체 흐름 검증 (`db/tools/import-flow-check.mjs`) | **27건 통과** — 실제 API·DB·파일 저장소를 거친다 |
| 권한 분리 | 승인 권한만 제거하니 승인은 403, 반려는 통과. 캐시 무효화 즉시 반영 |
| 화면 | 승인·반려 실제 클릭 동작, 모달 포커스 트랩·스크롤 잠금·복원 확인 |

**발견하고 고친 결함 2건 — 둘 다 화면에 실제 데이터를 띄워 보고서야 드러났다**

| # | 내용 | 조치 |
|---|---|---|
| 1 | **모든 업로드가 0바이트로 저장돼 파일 내용이 전멸**. 매직바이트 검사용 `part.file.once('data')` 가 스트림을 flowing 모드로 바꿔 `pipeline()` 보다 먼저 청크를 삼켰다. 작은 파일은 청크가 하나뿐이라 통째로 사라졌고, 전부 빈 입력의 sha256 하나로 중복제거됐다 | 해싱·크기·앞머리 엿보기를 **파이프라인 안의 Transform 하나**로 옮겼다. 0바이트 거부와 매직바이트 검사를 회귀 테스트로 고정 |
| 2 | 검수 대기 목록의 **업체 칸에 "Rev05"** 가 떴다. `coalesce(v.name, fl.vendor_labeled_rev)` 로 적어 업체가 없으면 리비전 표기가 새어 나왔다 | `files.vendor_name` 컬럼 추가(`0011`) — 기존 시스템도 반입 당시 이름을 따로 들고 있었다 |

> 1번은 데이터 유실 사고로 이어질 수 있었던 결함이다. **스트림에 곁다리 `data` 리스너를
> 붙이지 않는다**는 규칙을 `core/blob.ts` 주석과 README 규약에 남겼다.
