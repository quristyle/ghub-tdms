# 03. 백엔드 설계

## 1. 모듈 구조 — 기존 라우터와 1:1

```
packages/api/src/modules/
  auth/        users/       groups/      projects/     vendors/     type-lists/
  documents/   files/       favorites/   imports/      editor/
  distributions/
  mdb/         mdb-editor/  mdb-tag-history/
  audit/       backup/      preview/     jobs/
```

이름을 기존 라우터와 맞춘 이유는 **누락 여부를 폴더 목록만 봐도 알 수 있게** 하기 위해서다.

### 모든 모듈은 같은 4개 파일만 가진다

| 파일 | 책임 | 금지 |
|---|---|---|
| `routes.ts` | 경로·권한·감사·스키마 **선언만** | 업무 로직 |
| `service.ts` | 업무 규칙, 트랜잭션 경계 | SQL 문자열, 파일시스템 직접 접근 |
| `queries.ts` | **SQL 은 오직 여기에만** | 업무 분기 |
| `schema.ts` | `@tdms/contracts` 재노출 | 독자 타입 정의 |

이 규칙 하나가 장기 관리성의 핵심이다. *"이 쿼리가 왜 느린가"* 를 찾을 때 `queries.ts`만
보면 되고, 느린 쿼리 전수 조사가 `grep` 한 번으로 끝난다.

## 2. 권한·감사를 "빠뜨릴 수 없게" 만들기

기존 시스템의 가장 큰 운영 리스크는 두 가지이고, 둘 다 **사람이 기억해야 하는 구조**라서
생긴 누락이다.

- S-06: 권한 트리에 없는 기능은 로그인만 하면 전부 열림
- S-07: PDF 인라인 열람은 감사 미기록

선언형으로 바꿔 구조적으로 막는다.

```ts
// routes.ts
app.post('/editor/folders/reparent', {
  permission: 'screen.tdb_editor.folder',          // 36개 리프 중 하나. 타입으로 강제
  audit: { screen: 'TDB 관리', action: '폴더 이동' },
  schema: { body: FolderReparentRequest, response: { 200: FolderReparentResult } },
}, handler)
```

### 기동 시점 검증 — 하나라도 어긋나면 서버가 뜨지 않는다

```ts
assertEveryMutatingRouteDeclaresPermissionOrPublic(app)
assertEveryPermissionKeyExistsInTree(app)      // 리프 36개와 대조
assertEveryFileRouteDeclaresAudit(app)
assertEveryRouteHasResponseSchema(app)         // 직렬화 컴파일 보장 = 성능
```

### 권한 키는 타입이다

```ts
export const LEAF_KEYS = ['screen.tdb_list.access', ...] as const   // 36개
export type PermissionKey = typeof LEAF_KEYS[number]
```
트리에 없는 키를 쓰면 컴파일 에러가 난다.

### 감사 기록은 미들웨어가 쓴다

핸들러가 성공으로 끝나면 `audit` 선언을 보고 자동으로 `audit_log`에 적는다.
핸들러는 `reply.auditTarget('도면번호 A-123')` 로 대상만 덧붙인다.
**핸들러가 감사 기록을 잊을 방법이 없다.**

## 3. 캐시

```ts
// 프로세스 내 LRU. 무효화는 PostgreSQL 이 방송한다
pg.on('notification', (msg) => caches[msg.channel]?.clear())
await pg.query('LISTEN cache_perm; LISTEN cache_tree; LISTEN cache_types')
```

| 대상 | TTL | 효과 |
|---|---|---|
| 사용자별 권한 리프 | 60초 | 기존: 매 요청 DB 조회 |
| 폴더 트리 뼈대 | 영구 | 트리 펼치기 < 30ms |
| 타입 목록 | 영구 | 검색 화면 초기 로드 0 쿼리 |

변경 작업은 트랜잭션 커밋 후 `NOTIFY cache_tree` 를 보낸다.
단일 프로세스여도 이 구조를 지키면 **나중에 프로세스를 늘릴 때 코드 변경이 없다.**

## 4. 작업 큐와 진행률

```
POST /api/documents/export        → jobs INSERT → 202 {jobId}
GET  /api/jobs/:id/stream  (SSE)  → 진행률 수신
GET  /api/jobs/:id/download       → X-Accel-Redirect
```

대상 작업: 엑셀 내보내기 17종, Zip 반출/빌드, 백업 생성, DWG·오피스 변환,
대량 반입(Zip 등록), `최신` 미러 재구성, blob GC, 감사 파티션 생성.

진행률 UI(`JobProgress.vue`)는 **하나를 만들어 전부에 재사용**한다.
기존 백업 화면에만 있던 진행률 경험이 모든 장시간 작업으로 확장된다.

## 5. 파일 전송

```ts
// 앱이 하는 일: 권한 검사 + 감사 기록 + 헤더. 전송은 nginx 가 커널 sendfile 로.
reply
  .header('X-Accel-Redirect', `/_blob/${hex.slice(0,2)}/${hex.slice(2,4)}/${hex}`)
  .header('Content-Disposition', contentDisposition(displayName))
  .header('Content-Type', mime)
  .send()
```

개발 환경(nginx 없음)에서는 같은 핸들러가 `sendFile`로 떨어지게 분기한다.

## 6. 인증

| 항목 | 방식 |
|---|---|
| 비밀번호 | PBKDF2-HMAC-SHA256 600,000회 (기존 유지) |
| 세션 | DB 세션 테이블 + httpOnly/Secure/SameSite=Strict 쿠키 |
| 로그인 실패 | 5회 연속 실패 시 15분 잠금. 없는 계정도 동일 시간 소모(열거 방지) |
| 최초 비밀번호 | `ghub` + 아이디. 첫 로그인 시 변경 화면, 미루기 가능 (기존 정책 유지) |
| 비밀번호 변경 | 해당 사용자의 **모든 세션 무효화** |
| CSRF | Origin 동일 출처 검사 + SameSite=Strict (2중) |

> 초기 비밀번호 규칙은 기존 CM 결정이며 보안진단에서 지적될 수 있는 항목이다.
> 기능 보존을 위해 유지하되, `users.must_change_password`로 강제 변경 경로를 남긴다.

## 7. 에러 모델

```ts
// 모든 실패는 타입이 있는 코드로. 메시지는 화면이 번역한다
throw new AppError('FOLDER_NOT_EMPTY', { folderId, docCount })
```

| HTTP | 용도 |
|---|---|
| 400 | 입력 검증 실패 (Zod가 자동 생성) |
| 401 | 미로그인 |
| 403 | 권한 없음 (어떤 권한이 필요한지 코드로 반환) |
| 404 | 대상 없음 |
| 409 | 업무 규칙 위반 (중복, 상태 불일치) |
| 413 | 업로드 초과 |
| 422 | 처리 가능하나 거부 (예: 병합 필요 상태) |

## 8. 로깅·관측

| 항목 | 수단 |
|---|---|
| 애플리케이션 로그 | `pino` JSON → journald. 요청마다 `request_id` |
| 느린 쿼리 | `log_min_duration_statement=200ms` + `pg_stat_statements` 주간 Top 20 |
| 지표 | `/api/metrics` Prometheus 포맷 — 지연 p50/p95/p99, 큐 적체, 풀 사용량 |
| 작업 실패 | `jobs.state='failed'` 를 화면 배지로 노출 |

비밀값은 로그에 남지 않도록 `pino` redact 목록으로 차단한다.

## 9. 워커 (Python)

```
packages/worker/
  tdms_worker/
    __main__.py      LISTEN/NOTIFY 루프 + SKIP LOCKED 획득
    handlers/
      convert.py     DWG→PDF (ODA + ezdxf + PyMuPDF), 오피스→PDF (LibreOffice)
      zip_build.py   반출 Zip 생성
      excel.py       엑셀 내보내기 (수식 무력화 포함)
      backup.py      pg_dump / restic 호출
      bulk_import.py Zip 폴더 대량 등록
      mirror.py      blob → 최신 폴더 하드링크 재구성
      gc.py          refcount 0 blob 수거
```

- 외부 프로그램은 **리스트 인자만**, `shell=True` 미사용 (기존 정책 유지)
- 변환 타임아웃 초과 시 중단하고 "미리보기를 만들 수 없음"으로 기록
- systemd 샌드박싱: `PrivateNetwork=yes`(변환 워커는 네트워크 불필요), `ProtectSystem=strict`,
  `ReadWritePaths=/srv/tdms/blobs /srv/tdms/tmp`, `MemoryMax=2G`, `CPUWeight=50`

## 10. 테스트

| 층 | 도구 | 대상 |
|---|---|---|
| 단위 | Vitest | 리비전 상태 전이, 권한 cascade, 이름 규칙 |
| 통합 | Vitest + 로컬 PG | `queries.ts` 전수. 템플릿 DB 복제로 빠른 초기화 |
| 계약 | Vitest | 기존 OpenAPI 스냅샷 대조 (`baseline/openapi.json`) |
| E2E | Playwright | 화면 14개 요소 체크리스트, 주요 흐름 5개 |
| 부하 | k6 | 목록 p95 < 200ms 게이트 |

**DB 테스트 속도**: `CREATE DATABASE tdms_test_N TEMPLATE tdms_test_base` 로
파일마다 1초 내 초기화한다.
