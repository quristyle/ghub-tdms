05개발 방향성

개발 방향성 — 3원칙

기능 100% 보존 · 관리성과 성능 1순위 · 동등성은 증명

원칙 1

기능을 깎지 않는다

메뉴 9 · 화면 14 · 권한 36 · API 201을 전수 목록으로 고정하고 그대로 재현합니다.

쓰시던 화면 구성과 용어를 그대로 두어 재교육 부담이 없습니다. 범위 축소는 CM 결정 사항입니다.

원칙 2

관리성과 성능이 1순위

같은 기능을 고치기 쉬운 구조로 다시 짭니다 — 타입 1벌 공유, 권한·감사는 선언하지 않으면 서버가 뜨지 않습니다.

성능 기준을 자동 검사에 걸어 느려지면 빌드가 실패합니다.

원칙 3

동등성은 증명한다

① API 201개 계약 대조 ② 화면 요소 자동 대조 ③ 신·구 서버 응답 비교(섀도 2주)

데이터 이행은 건수와 sha256 전수 일치로 확인합니다. 눈 검사로 대체하지 않습니다.

06개발 방향성

바꾸지 않는 것 — 업무 규칙

CM이 확정해 둔 규칙은 설계 문서가 아니라 실행되는 테스트로 고정했습니다

규칙신규 시스템에서
삭제 기능이 없다보관함(삭제·폐기)으로 옮기고 복구 가능 — 어떤 경우에도 줄을 지우지 않습니다
도면을 자동 병합하지 않는다A·B 업체 동시 수정은 분기로 각각 보관 + ‘병합 필요’ — 사람이 CAD로 합친 것만 정식 Rev
리비전은 승인돼야 오른다반려는 정수를 소모하지 않고 글자(a·b·c)로 이력에 남습니다
감사 로그는 고칠 수 없다애플리케이션이 아니라 DB 권한 수준에서 수정·삭제를 차단합니다
‘최신’ 폴더는 그대로 남는다야간 배치가 하드링크로 재구성 — 탐색기에서 그대로 복사해 가실 수 있습니다
중복 반출을 막지 않는다경고만 합니다 — 막으면 분기 흐름이 성립하지 않습니다

08개발 방향성

핵심은 하나 — 파일을 움직이지 않는다

폴더를 바꾸든 리비전을 올리든 디스크는 그대로. DB 트랜잭션만 돕니다

작업기존 (경로 기반)신규 (내용 해시 기반)
폴더 이름 변경 (하위 500건)문자열 500건 수정 + 디스크 이동 500건줄 1개 수정 — 수십 초 → 1ms 미만
리비전 승인 · 자료 이동디스크 rename·이동 + DB 수정DB 수정만 — 디스크 작업 0
같은 파일 중복그대로 중복 저장내용이 같으면 한 벌만 저장
작업 중간 실패DB와 디스크가 어긋남 — 수동 복구되감기로 끝 — 정합성 보장

‘최신’ 폴더는 그대로 유지됩니다. 야간 배치가 하드링크로 트리를 다시 만들어 두므로 디스크를 추가로 쓰지 않습니다.
