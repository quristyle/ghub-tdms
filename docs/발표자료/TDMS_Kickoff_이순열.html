현행 시스템은 기능이 모자란 것이 아니라 구조가 업무를 따라가지 못합니다.

  • 성격: 기존 API 201개 중 순수 조회 12%, 파일 상태 전이 · 워크플로 88%

고쳐야 할 3가지

기능의 문제가 아니라 구조의 문제입니다. 부분 수정으로는 풀리지 않습니다.

① 폴더가 문자열이다

이름 한 번 바꾸면 수천 건 수정 + 디스크 이동

중간에 실패하면 DB와 디스크가 어긋난다

② 파일명이 메타데이터

리비전이 오르면 파일 이름이 바뀐다

승인 1건마다 디스크 작업 + 같은 파일이 여러 벌

③ 장시간 작업이 동기 실행

큰 건을 돌리면 화면이 수십 초 멈춘다

그동안 다른 사용자의 조회까지 느려진다

세 가지 모두 파일을 움직이지 않는 구조(폴더 테이블 · 내용 해시 저장 · 작업 큐)로 풀었다

목표 시스템 아키텍처

프로세스 3종(API · 워커 · DB)과 nginx 파일 직송 구조로 장애 지점과 운영 부담을 줄입니다.

  • 브라우저(Vue 3) → nginx(TLS · IP 제한 · 업로드 제한) → API(Fastify)
  • 파일은 nginx가 직송 — 애플리케이션이 파일 바이트를 만지지 않는다
  • 저장소: 내용 해시(sha256) blob — 불변 · 중복 제거 · 디스크 작업 0
  • PostgreSQL 16: 업무 데이터 · 세션 · 폴더 트리 · 한글 검색 · 작업 큐
  • 워커(Python 3.12): DWG · 오피스 변환 · Zip · 엑셀 · 백업 · 대량 반입
