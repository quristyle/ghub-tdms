# 04. 프론트엔드 설계

## 1. 스택

| 항목 | 선택 |
|---|---|
| 코어 | Vue 3.5 + Vite + TypeScript (`strict`, `noUncheckedIndexedAccess`) |
| 라우팅 | vue-router, 라우트별 코드 스플리팅 |
| 서버 상태 | TanStack Query (Vue) |
| 클라이언트 상태 | Pinia (세션·권한·장바구니·UI만) |
| 테이블 | TanStack Table (headless) + TanStack Virtual |
| 팝오버 | Floating UI |
| 유틸 | VueUse |
| PDF | `pdfjs-dist` 6.x + 기존 `dms-*.js` 17개 + `patch-package` |

## 2. 시각 언어 (2026-10-25 개정)

처음에는 기존 `style.css` 를 그대로 옮겨 픽셀 단위로 재현했다. 이후 CM 지시로
대시보드 계열(shadcn/apex)의 시각 언어를 입혔다. **화면 구성·메뉴·기능은 그대로**이고
바뀐 것은 보이는 층뿐이다.

| 가져온 것 | 이 제품에 맞춘 조정 |
|---|---|
| 토큰 기반 중성 팔레트 + 다크 모드 | 강조색은 SK가스 레드 유지 — 브랜드다 |
| 왼쪽 사이드바 내비게이션 | **메뉴 9개의 순서 그대로**. 도면·데이터북·운영 3묶음은 그 순서를 끊은 것뿐 |
| 카드 보더 + 8px 모서리, 배지·필 | 기본 여백은 널널하다 → **표 밀도 유지**(행 30px) |
| 밑줄 탭, 고스트 버튼 | 숫자·도면번호에 `tabular-nums` — 세로로 줄이 맞는다 |

**색은 직접 쓰지 않는다.** `styles/tokens.css` 한 곳을 거친다. 그래야 다크 모드가 한 벌로
끝나고, 상태 색(정상·검수대기·대여중·미입고)이 화면마다 달라지지 않는다.
명암비는 두 테마 모두 본문·보조 글자·상태 배지가 4.5:1 을 넘는다.

### 왼쪽이 두 겹이 되는 문제

트리를 쓰는 화면(TDB 조회·관리, MDB 조회·관리)은 내비 + 트리로 왼쪽이 두 겹이 된다.
내비를 아이콘 레일(56px)로 접을 수 있게 했고, **고른 적이 없으면** 좁은 화면에서 접어 둔다.
미디어 쿼리로 폭을 못박지 않는다 — 그러면 사용자가 펼치려 해도 펼쳐지지 않는다.

## 3. 컴포넌트 프레임워크를 쓰지 않는 이유

키트(PrimeVue·Element Plus)를 쓰면,

1. 토큰을 덮어쓰느라 CSS 오버라이드가 쌓인다
2. 번들이 커진다
3. 3년 뒤 메이저 버전업에 끌려다닌다

셋 다 관리성과 성능 모두에 손해다. 대신 **내부 컴포넌트 11종**으로 화면 14개를 전부 덮는다.
시각 언어를 통째로 바꾼 이번 작업에서도 고친 곳은 토큰·공통 스타일·셸이 전부였고,
화면 14개의 지역 스타일은 색 상수 몇 개만 토큰으로 바꿨다.

```
packages/web/src/ui/
  DataTable.vue        TanStack Table + Virtual. 정렬·선택·고정열
  LazyTree.vue         가상화 트리 + 자식 지연 로딩
  Modal.vue            포커스 트랩, ESC, 스크롤 잠금
  Popover.vue          Floating UI
  SearchBar.vue        조건 필드 묶음 + 디바운스 + 조건 초기화
  Pager.vue            처음/이전/다음/끝 + 페이지 직접 입력 (기존 UI 그대로)
  Cart.vue             반출대기함 / 다운대기함 공용
  JobProgress.vue      SSE 진행률 (엑셀·Zip·백업 공용)
  PermissionTree.vue   36리프 Y/N + 상위 cascade
  FileDrop.vue         업로드 (재개 가능)
```

기존 `style.css`에서 색·간격·글꼴을 **디자인 토큰**으로 추출해 `tokens.css`에 둔다.

## 4. 화면 14개와 라우트

| 라우트 | 화면 | 접속 권한 |
|---|---|---|
| `/` | TDB 조회 | `screen.tdb_list.access` |
| `/import` | TDB 반입·검수 | `screen.tdb_import.access` |
| `/editor` | TDB 관리 | `screen.tdb_editor.access` |
| `/distributions` | TDB 반출이력 | `screen.tdb_distributions.access` |
| `/mdb` | MDB 조회 | `screen.mdb_list.access` |
| `/mdb-editor` | MDB 관리 | `screen.mdb_editor.access` |
| `/audit` | 시스템 로그 | `screen.audit.access` |
| `/users` | 사용자 관리 | `screen.users.access` |
| `/groups` | 권한 관리 | `screen.users.access` |
| `/backup` | 백업 관리 | `screen.backup.access` |
| `/documents/:id` | TDB 상세 | 공용 |
| `/mdb/:id` | MDB 상세 | 공용 |
| `/help` | 도움말 | 공용 |
| `/login` | 로그인 | 없음 |

상단 메뉴 9개는 전 화면 고정, 순서 유지.
권한 없는 메뉴는 링크에서 제거되고, 주소 직접 입력 시 **서버가** 접근 가능한 첫 화면으로
리다이렉트한다(화면 코드만으로 막지 않는다 — 기존 정책 그대로).

## 5. 성능 장치

| 장치 | 효과 |
|---|---|
| **TanStack Virtual** | 1만 행 목록의 DOM 노드가 40개. 스크롤 60fps |
| **TanStack Query 캐시** | 상세 → 뒤로가기 시 네트워크 0회, 즉시 렌더 |
| **행 hover 시 상세 prefetch** | 클릭 시 체감 0ms. **120ms 머문 뒤에만** 쏜다 — 그대로 흘리면 그리드를 한 번 쓸 때 지나친 행마다 요청이 나간다(DataTable 의 onRowEnter) |
| **라우트별 코드 스플리팅** | 첫 진입 번들 < 150KB (gzip) |
| **PDF 뷰어 지연 로드** | 13MB를 상세 화면 진입 시에만 |
| **로그인 직후 선행 로드** | 트리 뼈대 + 타입 목록(업체·공사·설비유형) |
| **검색 디바운스 + AbortController** | 타이핑 중 중간 요청 취소 |
| **장바구니 Pinia 로컬** | 반출대기함 담기/빼기에 서버 왕복 없음 |
| **keyset 페이징** | "끝 페이지"도 첫 페이지와 같은 속도 |

### 캐시 수명 기준

| 자원 | staleTime |
|---|---|
| 타입 목록(업체·공사·설비유형·자료유형) | 무한 (변경 시 수동 무효화) |
| 폴더 트리 | 5분 |
| 목록·검색 결과 | 30초 |
| 상세 | 30초 |
| 검수 대기 / 미입고 (업무 대기열) | 0 (항상 최신) |

## 6. 타입 계약

```
packages/contracts/   Zod 스키마 1벌
        ├─→ Fastify 런타임 검증 + 응답 직렬화 컴파일
        ├─→ OpenAPI 3.1 자동 생성
        └─→ 프론트 API 클라이언트 자동 생성 (openapi-typescript)
```

```ts
// features/tdb-list/api.ts — 수작업 타입 없음
const { data } = useQuery({
  queryKey: qk.documents.list(params),
  queryFn: () => api.GET('/documents', { params }),   // 응답 타입 자동 추론
  staleTime: 30_000,
})
```

API 응답 필드 하나를 바꾸면 프론트가 `tsc`에서 컴파일 에러로 알려준다.
테스트 0건 상태를 물려받지 않기 위한 1차 방어선이다.

## 7. PDF 뷰어 이식

기존 `frontend/assets/pdfjs/web/dms-*.js` 17개(8,400줄)를 **그대로** 가져온다.

| 파일 | 기능 |
|---|---|
| `dms-viewer.js` | 진입점. 아래 모듈을 동적 import |
| `dms-tools.js` | 도구모음 확장 (고정·선택·손도구·회전·이동, 색·두께·선타입) |
| `dms-shapes.js` | 도형 (사각/타원/삼각/밸브/블라인드/직선/화살표/글자도형) |
| `dms-geometry.js` | 도형 좌표 계산 |
| `dms-stamp.js` | 스탬프 (Blind List 확인 등) |
| `dms-rotate.js` | 표시 회전 (Shift 15도 스냅) |
| `dms-copy.js` | Ctrl+끌기 복사, 고무줄 다중 선택 |
| `dms-eraser.js` | 지우개 |
| `dms-fill.js` / `dms-colors.js` | 채우기 / 색상 |
| `dms-edit-toolbar.js` | 선택 시 뜨는 소형 도구모음 |
| `dms-link.js` | 링크 |
| `dms-favorite.js` | 보관하기 / 다른 이름으로 보관 |
| `dms-source-switch.js` | 원본/사본 전환 |
| `dms-state.js` | 상태 |
| `dms-shapes.css` / `dms-tools.css` | 스타일 |

**이식 방법**

1. `pdfjs-dist` 를 npm 의존성으로 설치 (현재와 같은 6.x)
2. `pdf.worker.mjs` 의 2줄 패치를 `patch-package` 로 고정
3. `viewer.html` 에 `<script src="dms-viewer.js" type="module">` 한 줄 추가
4. `dms-favorite.js` 가 쓰는 외부 연동점만 Vue 쪽으로 연결
   - `window.dmsMarkup.collect()` → 마크업 JSON 수집 (그대로)
   - 보관 팝업 열기 → Vue `Modal` 로 교체
   - 마크업 저장 위치: 파일(`즐겨찾기/`) → **DB(`user_favorites`)**

마크업 데이터를 DB로 옮기면 검색·공유·권한이 따라온다.

## 8. 접근성·브라우저

- 대상: Chrome 기준, Edge 호환 확인 (기존과 동일)
- 메신저 인앱 브라우저 대응 (`index.html` 즉시 실행):
  - 카카오톡 링크 유입 시: `kakaotalk://web/openExternal?url=...` 호출로 시스템 기본 브라우저 자동 전환
  - LINE 링크 유입 시: `openExternalBrowser=1` 쿼리 파라미터 적용
  - Android 기타 인앱: Chrome Intent(`intent://...#Intent;scheme=https;package=com.android.chrome;end`)로 기본 브라우저 실행
  - 차단/미지원 환경 대비: 상단 가이드 배너(외부 브라우저 열기, 링크 복사, 다른 브라우저/Safari 열기 메뉴 안내) 제공
- 키보드: 목록 상하 이동, Enter 상세, Space 선택, ESC 모달 닫기
- 포커스 트랩: 모든 모달
- 한글 입력: IME composition 중 검색 디바운스 억제
