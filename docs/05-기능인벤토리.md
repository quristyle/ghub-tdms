# 05. 기능 인벤토리 — 재현 대상 전수 목록

기존 시스템에서 **빠짐없이 재현해야 할 것**의 기준 문서.
구현 진행 시 이 문서의 체크박스를 채워 나간다.

| 구분 | 수량 |
|---|---|
| 상단 메뉴 | 9 |
| 화면(HTML) | 14 |
| 권한 리프 | 36 (페이지 접속 10 + 기능 26) |
| API 엔드포인트 | **201** (문서상 "189"는 `type_lists` 팩토리 3벌 전개 누락) |

---

## 1. 상단 메뉴 (9개 · 전 화면 고정 · 순서 유지)

```
TDB 조회 │ TDB 반입·검수 │ TDB 관리 │ TDB 반출이력 │ MDB 조회 │ MDB 관리 │ 시스템 로그 │ 사용자 관리 │ 백업 관리
```

- 권한 없는 메뉴는 링크에서 **제거**된다.
- 주소를 직접 입력하면 **서버가** 접근 가능한 첫 화면(위 순서 기준)으로 리다이렉트한다.
- 접근 가능한 화면이 하나도 없으면 안내 화면(403)을 보여준다.

#### 3.8.1 신원·조직 (2026-10-26 추가 — 레거시에는 없던 것)
레거시 users 테이블은 아이디·이름·권한뿐이었다. 반출 기록에 "누가 가져갔나"를
이름 하나로만 남기면 동명이인과 퇴직자가 구분되지 않는다. G.Hub 포털이 들고 있던
신원·조직을 TDMS 가 직접 관리한다.
- [ ] 사번 / 입사일
- [ ] 부서 / 직위
- [ ] 소속 구분(companyCode) / 협력업체
- [ ] 내선 / 휴대전화 / 이메일
- [ ] 직전 접속일(previousLoginAt) · 포털 동기화 시각(syncedAt)
- [ ] 목록 거르기: 부서 선택 + 재직상태 + 통합검색(아이디·이름·사번·부서·직위·연락처·소속사)
- [ ] 협력업체 목록 `GET /partner-companies` (업체별 소속 인원수)

포털에서 받았지만 TDMS 가 쓰지 않는 값(알림 설정·모바일 배치·연차·생년월일)은
`users.portal_profile` jsonb 에 그대로 담아 둔다. 화면에 내보내지 않는다 —
도면관리 시스템에 연차 편집기를 둘 이유가 없고, 버리면 되돌려 줄 수 없다.

동기화: `node db/tools/import-users.mjs <포털응답.json>` (여러 번 돌려도 결과가 같다).
비밀번호·권한·그룹은 가져오지 않는다 — 포털 해시를 모르고, 부서명을 TDMS 권한그룹에
자동으로 꽂으면 권한이 소리 없이 열린다.

### 권한 규칙 (기존 정책 그대로 승계)
1. 트리 구조는 **코드에 고정**한다. 화면에서 노드를 추가·삭제할 수 없다.
2. 상위 노드를 Y로 켜면 하위가 전부 Y가 된다(화면 cascade). 저장은 항상 **leaf 키**로 푼다.
3. `role=ADMIN` 은 항상 전체 통과.
4. **트리에 없는 기능은 로그인한 사람 누구나 쓴다** (2026-08-12 CM 확정).
5. 화면 파일을 내려줄 때 **서버가 먼저** 권한을 본다. 화면 코드만으로 막지 않는다.
