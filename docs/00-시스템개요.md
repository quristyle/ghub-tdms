# 00. 시스템 개요

## 1. 이 시스템은 무엇인가

SK가스 G.Hub 사업장의 **도면(TDB)**과 **설비 데이터북(MDB)** 을 관리하는 사내 웹 시스템.

| 항목 | 값 |
|---|---|
| 도면 | 10,827건 / 파일 약 16,400개 / 약 6.5GB |
| MDB 자료 | 약 1,200건 |
| 사용자 | 설비기술팀 CM 및 사내 동료 (수십 명) |
| 협력사 | 시스템 접근 없음. 파일은 CM이 반출하여 전달 |
| 외부 연동 | 없음 |

## 2. 겉보기와 실제

**겉보기**: 도면 1만 건을 검색·열람하는 시스템
**실제**: 파일 상태 머신 + 워크플로 엔진

기존 API 201개의 분포가 이를 보여준다.

| 라우터 | API 수 | 성격 |
|---|---|---|
| `editor` | 31 | CM이 폴더·자료를 직접 정리하는 편집기 |
| `mdb_editor` | 29 | 데이터북 편집 |
| `distributions` | 18 | 협력사 반출·반납·미입고 |
| `imports` | 17 | 대량 반입·검수·승인 |
| `type_lists` | 18 | 설비유형·자료유형·사유 (팩토리 3벌) |
| `documents` + `mdb` | 25 | **실제 조회 기능** |
| 나머지 | 63 | 권한·감사·백업·즐겨찾기(마크업)·미리보기 |

조회는 12%, 나머지 88%가 "파일을 옮기고·이름 바꾸고·리비전을 올리고·되살리는" 로직이다.
따라서 성능 설계의 중심은 **목록 렌더링이 아니라 파일시스템과 DB의 정합성을 지키면서
상태 전이를 싸게 만드는 것**이다.

## 3. 두 개의 도메인

| 도메인 | 성격 | 가지는 것 | 없는 것 |
|---|---|---|---|
| **TDB (도면)** | 살아있는 자료 | 리비전, 반출, 검수, 분기(병합필요) | — |
| **MDB (데이터북)** | 고정 기록 | 태그 이력, 설비유형 분류 | 리비전, 반출, 검수 |

기존 시스템은 둘을 같은 화면 체계로 묶어 코드가 비대해졌다.
**신규 시스템은 테이블과 컴포넌트를 공유하지 않는다.** 상위 UI 요소만 공유한다.

## 4. 절대 원칙 (기존 시스템에서 승계)

1. **삭제 기능이 없다.** 보관함(`is_archived`)·폐기 보관함으로 옮기고 복구 가능.
2. **CAD 도면은 자동 병합하지 않는다.** A·B 업체 동시 수정 시 분기 리비전으로 각각 보관하고
   `병합 필요` 상태를 부여한다. 사람이 CAD로 통합한 것만 정식 Rev로 승인한다.
3. **감사 로그는 수정·삭제할 수 없다.** DB 권한 수준에서 강제한다.
4. **권한 트리에 없는 기능은 로그인한 사람 누구나 쓴다.** (2026-08-12 CM 확정)

## 6. 기존 시스템에서 반드시 고칠 3가지

### ① 폴더가 테이블이 아니라 문자열이다
기존 `editor.py` 주석: *"폴더는 실제 테이블이 없는 가상 개념 — `documents.source_path`
문자열로만 존재한다."* 폴더 이름 하나를 바꾸면 수천 row의 문자열 접두어 UPDATE와
실제 디스크 파일 이동이 함께 일어난다. 중간에 실패하면 DB와 디스크가 어긋난다.

→ **`folders` 테이블 + `ltree`**. 이름 변경이 row 1개 UPDATE가 된다.

### ② DB 경로가 곧 디스크 경로이고, 파일명이 메타데이터를 들고 있다
기존 `storage.py`: `최신/{원본경로}/{도면번호}_Rev00.pdf` — 리비전이 오르면 파일 이름이 바뀐다.
승인 1건마다 디스크 rename과 DB UPDATE가 묶여 돈다.

→ **content-addressed blob**. 사람이 읽는 이름은 다운로드 시점에 만든다.
`최신` 폴더 요구는 야간 하드링크 미러로 충족한다.

### ③ 장시간 작업이 요청 스레드에서 동기 실행된다
엑셀 내보내기 17종, Zip 반출, 백업, DWG 변환이 모두 동기. 큰 건은 화면이 수십 초 멈춘다.

→ **PostgreSQL 작업 큐 + Python 워커 + SSE 진행률**.

## 7. 정정 사항 — PDF 뷰어는 포크가 아니다

인수인계 문서(`시스템_개요서.md` 4절, 요약표 S-21)는 *"PDF.js 원본 `viewer.mjs`·
`pdf.worker.mjs`를 직접 수정한 8,400줄 포크"* 라고 기술했으나, 코드 검증 결과 사실이 아니다.

| 대상 | 실제 수정량 |
|---|---|
| `web/viewer.mjs` | 0줄 |
| `build/pdf.mjs` | 0줄 |
| `build/pdf.worker.mjs` | 2곳 (`[DMS 수정]` 하이라이트 blend mode) |
| `web/viewer.html` | 1줄 (`<script src="dms-viewer.js">`) |
| `dms-*.js` 17개 (8,400줄) | 전부 덧붙인 별도 모듈 |

`dms-shapes.js` 헤더 주석도 명시한다 — *"PDF.js 안쪽 코드는 한 줄도 고치지 않으므로
새 버전으로 올릴 때도 이 파일들만 그대로 옮기면 된다."* PDF.js 버전은 6.3.289(최신 계열).

→ **뷰어·마크업은 재작성 대상이 아니라 그대로 이식하는 자산이다.**
2줄 패치는 `patch-package`로 고정해 업스트림 추적이 가능하게 한다.

## 8. 명시적 제외 (기존 범위 그대로)

Ocean-H 연동, 웹에서 DWG 직접 열람, DWG 내 설비정보 자동 추출, 도면 본문 전문검색,
Smart Tagging / P&ID Link, DRM, SSO, 도면 자동 병합.
