## 3. 성능을 결정하는 설계 3가지

### ① 폴더를 1급 테이블로 (`ltree`)

```sql
CREATE TABLE folders (
  id        bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  parent_id bigint REFERENCES folders(id) ON DELETE RESTRICT,
  doc_class text   NOT NULL CHECK (doc_class IN ('TDB','MDB')),
  name      text   NOT NULL,
  path      ltree  NOT NULL,
  depth     smallint GENERATED ALWAYS AS (nlevel(path)) STORED,
  doc_count integer NOT NULL DEFAULT 0,   -- 트리 배지. 트리거로 유지
  is_placeholder boolean NOT NULL DEFAULT false,  -- 빈 폴더
  UNIQUE (parent_id, name)
);
CREATE INDEX ix_folders_path   ON folders USING gist (path);
CREATE INDEX ix_folders_parent ON folders (parent_id, name);
```

`path`는 한글 폴더명을 그대로 담을 수 없다(`ltree`는 `[A-Za-z0-9_]`만 허용).
**폴더 id를 라벨로 쓴다** — `path = '1.14.57'` 형태. 사람이 보는 이름은 `name` 컬럼이다.
이렇게 하면 이름을 바꿔도 `path`가 바뀌지 않아 하위 갱신조차 필요 없다.

| 작업 | 비용 |
|---|---|
| 이름 변경 | `UPDATE folders SET name=$2 WHERE id=$1` — row 1개 |
| 위치 이동 | 자신과 하위의 `path` 접두어 교체 — `UPDATE ... WHERE path <@ $old` |
| 하위 전체 조회 | `WHERE path <@ $1` — GiST 인덱스 |
| 직계 자식 | `WHERE parent_id = $1` — B-tree |

### ② 검색 전용 생성 컬럼 + trgm GIN

```sql
ALTER TABLE documents ADD COLUMN search_text text
  GENERATED ALWAYS AS (drawing_no ||' '|| title ||' '|| coalesce(equipment_tag,'')) STORED;

CREATE INDEX ix_documents_search ON documents USING gin (search_text gin_trgm_ops);
```

`ILIKE '%...%'` 가 GIN 인덱스를 타게 된다. 한글 도면명에는 `tsvector`보다 trgm이 실용적이다
(형태소 분석기 없이 부분일치가 동작한다).

```sql
-- 가장 흔한 탐색 경로 전용 (전체의 63%인 Isometric 제외)
CREATE INDEX ix_documents_browse ON documents (folder_id, updated_at DESC, id DESC)
  WHERE status = 'ACTIVE' AND NOT is_archived AND NOT is_isometric;

-- 미입고 조회
CREATE INDEX ix_dist_outstanding ON distributions (distributed_at)
  WHERE returned_at IS NULL;

-- 현재본은 문서당 하나
CREATE UNIQUE INDEX ix_files_current ON files (document_id) WHERE is_current;
```

### ③ content-addressed blob

```sql
CREATE TABLE blobs (
  sha256    bytea  PRIMARY KEY,        -- 32바이트. text(64자)보다 인덱스가 절반
  byte_size bigint NOT NULL,
  refcount  integer NOT NULL DEFAULT 0,
  stored_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE files (
  id           bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  document_id  bigint NOT NULL REFERENCES documents(id),
  blob_sha256  bytea  NOT NULL REFERENCES blobs(sha256),
  rev          integer NOT NULL,
  branch       text,                   -- 분기 리비전 'a','b'
  file_ext     text   NOT NULL,
  display_name text   NOT NULL,        -- 사람이 보는 이름. 규칙이 바뀌어도 파일은 그대로
  review_status text  NOT NULL,
  is_current   boolean NOT NULL DEFAULT false,
  ...
);
```

디스크 경로는 `/srv/tdms/blobs/{hex[0:2]}/{hex[2:4]}/{hex}`.
`refcount`가 0이 된 blob은 야간 GC가 수거한다(즉시 삭제하지 않는다 — 복구 가능해야 하므로).

## 4. 핫 쿼리 작성 원칙

### 원칙 1 — `ltree` 조건을 큰 테이블 조인에 직접 걸지 않는다

플래너가 흔들린다. **폴더 id를 먼저 풀어서 배열로 넘기는 쪽이 항상 빠르다**
(folders는 수백 행이라 비용이 사실상 0이고, 캐시 대상이기도 하다).

```sql
-- 1단계: 서브트리 폴더 id
SELECT id FROM folders WHERE path <@ $1::ltree;

-- 2단계: 목록
... WHERE d.folder_id = ANY($2::bigint[])
```

### 원칙 2 — `OFFSET` 금지, keyset(cursor) 페이징

```sql
AND (d.updated_at, d.id) < ($5::timestamptz, $6::bigint)
ORDER BY d.updated_at DESC, d.id DESC
LIMIT 100
```
1페이지든 100페이지든 같은 속도다. 기존 "끝 페이지" 버튼이 느렸던 원인이 `OFFSET`이다.

### 원칙 3 — N+1 금지. 부가 정보는 `LATERAL`로 한 번에

```sql
LEFT JOIN LATERAL (
  SELECT vendor, distributed_at FROM distributions
  WHERE document_id = d.id AND returned_at IS NULL
  ORDER BY distributed_at DESC LIMIT 1
) lent ON true
```

### TDB 목록 전체 쿼리

```sql
SELECT d.id, d.drawing_no, d.title, d.current_rev, d.status,
       d.has_dwg, d.has_pdf, d.updated_at,
       lent.vendor AS lent_to, lent.distributed_at AS lent_at
FROM documents d
LEFT JOIN LATERAL (
  SELECT vendor, distributed_at FROM distributions
  WHERE document_id = d.id AND returned_at IS NULL
  ORDER BY distributed_at DESC LIMIT 1
) lent ON true
WHERE d.folder_id = ANY($1::bigint[])
  AND d.status = 'ACTIVE' AND NOT d.is_archived
  AND (NOT $2::boolean OR NOT d.is_isometric)
  AND ($3::text IS NULL OR d.search_text ILIKE '%'||$3||'%')
  AND ($4::timestamptz IS NULL OR (d.updated_at, d.id) < ($4, $5))
ORDER BY d.updated_at DESC, d.id DESC
LIMIT $6;
```

## 5. 감사 로그 — 영구 보존 + 빠른 조회

```sql
CREATE TABLE audit_log (
  id          bigint GENERATED ALWAYS AS IDENTITY,
  occurred_at timestamptz NOT NULL DEFAULT now(),
  user_id     bigint,
  screen      text,      -- 'TDB 관리'
  action      text,      -- '폴더 이동'
  target      text,      -- 자료명/파일명
  detail      jsonb,
  client_ip   inet,
  PRIMARY KEY (id, occurred_at)
) PARTITION BY RANGE (occurred_at);
```

- 월 단위 파티션. 각 파티션에 `occurred_at` BRIN 인덱스.
- 10년치가 쌓여도 기간 조회가 일정하다.
- **삭제 불가 정책을 DB 권한으로 강제한다**: `REVOKE DELETE, UPDATE ON audit_log FROM <app_role>`
- 다음 달 파티션은 작업 큐의 월간 잡이 미리 만든다.

## 6. 세션

```sql
CREATE TABLE sessions (
  id           text PRIMARY KEY,                       -- 256bit 랜덤 base64url
  user_id      bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  expires_at   timestamptz NOT NULL,
  last_seen_at timestamptz NOT NULL DEFAULT now(),
  client_ip    inet,
  user_agent   text
);
```

서명 쿠키(기존 S-03)를 대체해 **즉시 강제 로그아웃**이 가능해진다.

**성능 주의**: `last_seen_at`을 매 요청 UPDATE하면 쓰기 증폭이 크다.
**60초에 한 번만 갱신**한다.

## 7. 작업 큐

```sql
CREATE TABLE jobs (
  id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  kind          text NOT NULL,   -- excel_export|zip_build|backup|convert|bulk_import|mirror|gc
  payload       jsonb NOT NULL,
  state         text NOT NULL DEFAULT 'queued',  -- queued|running|done|failed|canceled
  priority      smallint NOT NULL DEFAULT 100,
  progress      smallint NOT NULL DEFAULT 0,
  progress_note text,
  result        jsonb,
  error         text,
  requested_by  bigint REFERENCES users(id),
  attempts      smallint NOT NULL DEFAULT 0,
  locked_by     text,
  heartbeat_at  timestamptz,
  created_at    timestamptz NOT NULL DEFAULT now(),
  finished_at   timestamptz
);
CREATE INDEX ix_jobs_pick ON jobs (priority, id) WHERE state = 'queued';
```

```sql
-- 워커의 획득 쿼리. 경쟁 없음, 폴링 없음(NOTIFY 로 깨어난다)
UPDATE jobs SET state='running', locked_by=$1, heartbeat_at=now(), attempts=attempts+1
WHERE id = (SELECT id FROM jobs WHERE state='queued'
            ORDER BY priority, id FOR UPDATE SKIP LOCKED LIMIT 1)
RETURNING *;
```

`heartbeat_at`이 2분 이상 끊긴 `running` 잡은 좀비로 보고 `queued`로 되돌린다.

## 8. PostgreSQL 설정 (운영 서버 16GB / 4 vCPU / NVMe)

```ini
shared_buffers = 4GB
effective_cache_size = 12GB
work_mem = 32MB
maintenance_work_mem = 1GB
random_page_cost = 1.1              # NVMe
effective_io_concurrency = 200
jit = off                           # ★ 짧은 OLTP 쿼리에서 JIT 는 오히려 손해
wal_compression = on
checkpoint_timeout = 15min
max_wal_size = 4GB
shared_preload_libraries = 'pg_stat_statements'
track_io_timing = on
log_min_duration_statement = 200ms
autovacuum_vacuum_scale_factor = 0.05
```

`jit = off`가 특히 중요하다. 기본값(on)이면 이런 목록 쿼리에서
**JIT 컴파일 시간이 쿼리 실행 시간보다 길어지는** 경우가 흔하다.
