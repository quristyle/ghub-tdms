## 3. 성능 회귀 방지 — CI 게이트

성능을 테스트로 고정하지 않으면 1년 안에 원래대로 돌아간다.

```yaml
# .github/workflows/ci.yml
- pnpm -r typecheck          # tsc --noEmit
- pnpm -r lint
- pnpm -r test               # Vitest 단위 + 통합
- pnpm --filter web size-limit   # 번들 예산 초과 시 실패
- pnpm test:e2e              # Playwright 화면 체크리스트
- pnpm test:perf             # k6 — p95 초과 시 실패
- pnpm audit && pip-audit    # CVE
```

## 6. 실측 결과 (2026-10-25, 52,000건 적재)

실제 규모(도면 10,827건)의 약 5배인 **52,000건**을 적재해 측정했다.
DB: PostgreSQL 16.15 @ jin114.co.kr:31015 / 스키마 `ghub_tdms`.

| 쿼리 | 실행시간 |
|---|---|
| 목록 1페이지 (전체 범위) | **0.07ms** |
| 목록 1페이지 (말단 폴더 1개) | **0.54ms** |
| 목록 (Isometric 포함) | **0.37ms** |
| 깊은 페이지 — keyset (37,000번째) | **2.45ms** |
| 한글 부분일치 (trgm GIN) | **1.57ms** |
| 도면번호 부분일치 | **9.44ms** |
| 폴더 서브트리 id (ltree GiST) | **0.64ms** |
| 폴더 직계 자식 | **0.35ms** |
| 상세 단건 | **0.12ms** |

전부 목표치(150ms) 아래다. 기존 시스템에서 수십 초 걸리던 폴더 편집이 1ms 미만이 되었다 —
파일을 움직이지 않고 DB 트랜잭션만으로 끝나기 때문이다.

### 측정 중 발견하고 고친 것 — 인덱스 선두 컬럼

처음 설계한 `ix_documents_browse (folder_id, updated_at DESC, id DESC)` 는
**목록 1페이지에서 쓰이지 않았다.** `folder_id = ANY(array)` 로 여러 폴더를 거르면
선두 컬럼이 범위가 되어 정렬에 쓸 수 없고, Seq Scan + top-N 정렬이 돼
**51ms** 가 걸렸다. (커서가 붙는 2페이지 이후는 선택도가 높아져 인덱스를 탔다.)

→ 정렬키만 선두로 둔 짝 인덱스를 추가했다 (`0008_browse_index_fix.sql`).

```sql
CREATE INDEX ix_documents_recent ON documents (updated_at DESC, id DESC)
  WHERE status = 'ACTIVE' AND NOT is_archived AND NOT is_isometric;
```

**51ms → 0.2ms (255배).** 넓은 범위는 이 인덱스로 `LIMIT` 에서 조기 종료하고,
좁은 범위(말단 폴더 하나)는 기존 `folder_id` 선두 인덱스를 쓴다. 플래너가 고른다.

> 교훈: 목록 쿼리의 인덱스는 **1페이지(커서 없음)를 기준으로** 검증해야 한다.
> 커서가 붙은 2페이지 이후만 보면 문제가 드러나지 않는다.

### API 엔드포인트 응답 (원격 DB 기준)

| 엔드포인트 | p50 | p95 |
|---|---|---|
| `GET /documents?limit=100` | 185ms | 231ms |
| `GET /documents` + 검색 | 124ms | 201ms |
| `GET /folders` | 35ms | 68ms |
| `GET /documents/:id` | 134ms | 159ms |
| `GET /health` (`SELECT 1`) | 54ms | 139ms |

쿼리 자체는 1ms 미만이므로 **이 수치는 전부 원격 DB 네트워크 왕복**이다
(`/health` 의 54ms 가 왕복 기준선). 운영 서버에서는 DB 가 같은 장비의 유닉스 소켓에 있으므로
**목록 p95 는 10ms 수준**이 된다. 현재 개발 DB 가 원격이라는 점만 감안하면 된다.
