# 07. DB 설계서 (확정판)

`03_도면체계_및_메타데이터.md`의 초안을 실제 스캔 데이터(10,827건)로 검증·확정한 버전.
Claude Code 개발 시 이 문서를 그대로 스키마 구현 기준으로 사용한다.

## 1. ERD 개요

```
users ──────┐
            │ (uploaded_by / distributed_by / reviewed_by)
            ▼
documents ──┬──< files (1:N, Rev별)
            │
            ├──< distributions (1:N, 배포 건별)
            │
            └──< audit_log (1:N)
```

### 2.2 `documents` — 문서 마스터

실제 데이터 검증 결과 반영. `area` 필드는 폴더 깊이가 disciplines마다 달라(Isometric은 5단계, Civil은 3단계 등) **가변 길이 텍스트로 저장**(경로 그대로, "/"로 결합)하는 것으로 확정. 무리하게 area를 세부 정규화(별도 테이블화)하지 않는다 — 실사용에서 검색 키는 어차피 도면번호이므로, area는 "표시용 참고정보" 성격으로 충분.

| 필드 | 타입 | 설명 | 비고 |
|---|---|---|---|
| `id` | PK | | |
| **`doc_class`** | enum | `DRAWING` / `MDB_RECORD` / `SPEC` / `CALC` / `REPORT` | 2차 확장 대비. 1차는 전량 `DRAWING` |
| `drawing_no` | text | 파일명(확장자 제외) 그대로 저장 | **고유 식별자로만 취급, 형식 파싱 안 함** — 87%가 비정형 |
| `title` | text | 도면명 (파일명과 동일하게 시작, 추후 편집 가능) | |
| `category` | text | 대분류 (예: "5. DRAWINGS") | 폴더 1단계 |
| `discipline` | text | 공종 (예: "5.1 Plot Plan & ELP & Piping Plan Drawing") | 폴더 2단계 |
| `doc_type` | text | 도면종류 (예: "5.1.2 Piping Plan Drawing (ISBL)") | 폴더 3단계 |
| `isbl_osbl` | enum | `ISBL` / `OSBL` / `제3부두` / `''` | 폴더명에서 추출 |
| `elevation` | enum | `AG` / `UG` / `''` | 폴더명에서 추출 (있는 경우만) |
| `area` | text | 나머지 하위 경로 (예: "AG/A AREA", "1.Cover & List/20S") | 표시용 |
| `is_isometric` | bool | discipline에 "Isometric" 포함 여부 자동 플래그 | **검색 UI 기본 필터에서 제외하기 위한 실사용 플래그** (요구사항 3.2) |
| `equipment_tag` | text | 설비 Tag | Ocean-H 연동 대비, 1차는 비워둠 |
| `current_rev` | text | 현재 리비전 (없으면 "0" 또는 공란) | |
| `status` | enum | `ACTIVE` / `CHECKED_OUT` / `MERGE_REQUIRED` / `PENDING`(P&ID 등 파일 미보유) / `SUPERSEDED` | |
| `has_dwg` | bool | | 인벤토리 스캔 결과 그대로 초기값 반영 |
| `has_pdf` | bool | | 동일 |
| `created_at` / `updated_at` | ts | | |

## 3. 초기 데이터 적재(Bulk Import) 매핑

`도면대장.xlsx` 컬럼 → `documents`/`files` 필드 매핑

| 엑셀 컬럼 | DB 필드 |
|---|---|
| 도면번호(파일명) | `documents.drawing_no`, `title` |
| 대분류 | `category` |
| 공종 | `discipline` (+ "Isometric" 포함 시 `is_isometric=true`) |
| 도면종류 | `doc_type` |
| ISBL_OSBL | `isbl_osbl` |
| 지상지하 | `elevation` |
| 구역 | `area` |
| DWG유무/PDF유무 | `has_dwg` / `has_pdf` → `files` 각각 1건씩(있는 것만) 생성, `rev="0"` |
| 최종수정일 | `files.uploaded_at` (등록자는 시스템 계정 "일괄등록") |

P&ID(`doc_type`에 "Process & Instrument" 포함)는 이 매핑에서 제외 — 실제 파일이 없으므로 D-9에 따라 **메타데이터만 관리자가 수기로 몇 건 선등록**하거나, 1차는 아예 비워두고 2차에 추가.

## 4. 인덱스 (성능)

| 테이블 | 인덱스 대상 | 이유 |
|---|---|---|
| `documents` | `drawing_no` (unique) | 검색 최다 사용 |
| `documents` | `discipline`, `doc_type`, `is_isometric` | 목록 필터링 |
| `distributions` | `document_id`, `returned_at` | 미입고 조회 |
| `distributions` | `download_token` (unique) | 토큰 접속 |
| `files` | `document_id`, `is_current` | 최신 파일 조회 |

## 5. API 엔드포인트 초안 (FastAPI, Claude Code 참고용)

```
GET    /documents                 # 목록/검색 (is_isometric 필터 기본 false)
GET    /documents/{id}            # 상세
POST   /documents/bulk-import     # 초기 적재 전용 (1회성)
POST   /documents/{id}/files      # 신규 파일(Rev) 등록

POST   /distributions             # 배포(링크 발급)
GET    /distributions/outstanding # 미입고 목록
GET    /distributions/{id}        # 배포 상세

GET    /vendor/{token}            # 협력사: 배포 도면 확인 (로그인 없음)
POST   /vendor/{token}/upload     # 협력사: 수정본 업로드
POST   /distributions/{id}/review # 사내: 검수 승인/반려

GET    /audit-log                 # 감사로그 조회 (관리자)
```
