# 06. 요구사항 정의서 (MVP)

## 1. 목적

실제 도면 인벤토리(10,827건) 분석 결과를 반영해, 1차 개발(MVP) 범위의 화면·기능·시나리오를 확정한다.
이 문서 확정 후 → `CLAUDE.md`로 변환 → Claude Code 개발 착수.

## 2. 사용자 역할 (3종)

| 역할 | 설명 | 주요 권한 |
|---|---|---|
| **관리자 (Admin)** | CM 등 시스템 운영자 | 전체 기능 + 사용자 관리 + 배포이력·미입고 현황 전체 조회 |
| **사내 사용자 (Internal)** | 설비기술팀 등 사내 담당자 | 도면 검색·열람·다운로드, 협력사 배포, 검수·승인 |
| **협력사 (Vendor)** | 외부 공사업체 | 본인에게 배포된 도면만 다운로드, 수정본 업로드 |

> 로그인은 사내용 계정(ID/PW)만 운영. 협력사는 **계정 없이 만료형 링크**로 접근(D-1·보안 개선안).

## 3. 기능 요구사항

### 3.1 도면 등록 (Registration)

| 항목 | 내용 |
|---|---|
| 방식 | 최초 1회 **일괄 등록**(Bulk Import) — 도면대장.xlsx 데이터를 그대로 적재 |
| 이후 신규 등록 | 관리자/사내 사용자가 개별 업로드 (DWG+PDF 세트 또는 PDF 단독) |
| 자동 처리 | 파일명(도면번호), 폴더 경로 → 공종/도면종류/ISBL·OSBL/지상지하/구역 **자동 매핑** |
| P&ID 예외 | `doc_type=P&ID` 항목은 **메타데이터만 선등록**, 파일 없이 "준비중" 상태로 표시 (D-9) |
| DWG 또는 PDF만 있는 경우 | 등록 허용. `쌍정상여부` 필드로 상태 표시, 시스템 정지 조건 아님 (D-10) |

### 3.2 검색·조회

| 항목 | 내용 |
|---|---|
| 트리 탐색 | 대분류 → 공종 → 도면종류 → ISBL/OSBL → 구역 순 폴더형 탐색 |
| 속성 검색 | 도면번호, 도면명, 공종, 구역, 상태로 검색 |
| **Isometric 별도 처리** | 전체의 63%(6,843건 중 Isometric류 다수)를 차지 → 기본 검색에서는 숨기고 **별도 탭/토글**로 분리 (안 그러면 목록이 압도적으로 Iso로 뒤덮임) |
| 목록 표시 | 도면번호 / 도면명 / Rev / 상태 / 최종수정일 |

### 3.3 열람

| 항목 | 내용 |
|---|---|
| PDF | 웹 브라우저 내 뷰어(PDF.js) — 즉시 열람 |
| DWG | 다운로드만 제공 (웹 열람 불가, D-1) |
| PDF 없는 도면 | "PDF 미보유" 안내 + DWG 다운로드 버튼만 노출 |

### 3.4 리비전(Rev) 관리

| 항목 | 내용 |
|---|---|
| 신규 Rev 등록 | 검수 승인 시점에만 생성 (3.6 참조) |
| 구본 처리 | 삭제 금지. `SUPERSEDED` 상태로 보관, 목록엔 "이력 보기"로만 노출 |
| 이력 조회 | 도면 상세화면에서 전체 Rev 이력(등록일, 등록자, 사유) 타임라인 표시 |

### 3.5 협력사 배포

| 항목 | 내용 |
|---|---|
| 배포 절차 | 사내 사용자가 도면 선택 → 업체명·공사번호 입력 → **만료형 링크 생성**(기본 7일) → 이메일 발송(수동 복사 또는 시스템 발송) |
| 워터마크 | 다운로드되는 PDF에 업체명+배포일자 자동 삽입 |
| 중복 대여 경고 | 이미 배포된 도면을 다른 업체에게 배포 시도 시 **"A업체 대여중(일자)" 경고 팝업**, 배포는 가능(강제 차단 아님) |

### 3.6 입고·검수

| 항목 | 내용 |
|---|---|
| 업체 업로드 | 협력사가 링크로 접근 → 수정 파일 업로드 (로그인 불필요, 토큰 기반) |
| 검수 대기 | 상태 `REVIEWED 대기`로 표시, 사내 담당자에게 알림(화면 표시. 이메일 발송은 2차 고려) |
| 승인 | 담당자가 검수 후 승인 → **신규 Rev로 등록**, 구본은 Superseded 처리 |
| 반려 | 반려 시 사유 입력, 업체에게 재업로드 요청 상태로 전환 |
| **동시 수정 (A·B 업체)** | B업체 요청 시 "A업체 대여중" 경고 → A/B 각각 **분기 Rev(C-a/C-b)**로 저장 → `병합 필요(Merge Required)` 상태 부여 → **담당자가 캐디안에서 수기 통합** 후에만 정식 Rev로 승인 (시스템이 자동 병합하지 않음, 절대 원칙) |

### 3.7 미입고 관리

| 항목 | 내용 |
|---|---|
| 목록 | 배포됐지만 `returned_at`이 비어있는 항목 전체 목록 |
| 정렬 | 배포일 오래된 순 |
| 용도 | 관리자가 주기적으로 업체 재촉 |

### 3.8 배포 이력

| 항목 | 내용 |
|---|---|
| 조회 | 도면별 / 업체별 / 기간별 배포 이력 검색 |
| 기록 항목 | 배포자, 배포일, 업체, 공사번호, Rev, 다운로드 여부·시각, 반납 여부 |

### 3.9 권한·감사로그

| 항목 | 내용 |
|---|---|
| 로그인 | 사내 계정(ID/PW), 3단계 역할 |
| 감사로그 | 등록/배포/승인/반려 등 모든 변경행위 기록. **삭제 불가** |

## 4. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 데이터 규모 | 10,000건+ 도면, 6.5GB+(향후 증가 대비 20GB 이상 여유) |
| 목록 응답 속도 | 검색·목록 조회 2초 이내 (Isometric 별도 탭 분리로 목표 달성) |
| 배포 links | 7일 만료, 1회성 원칙(재배포 시 새 링크 발급) |
| 배포 환경 | 1단계: CM PC 로컬(Docker Compose) / 3단계: 사내 VM 이관 |
| 브라우저 | Chrome 기준 (Edge 호환 확인) |

## 6. 제외 범위 (재확인)

`01_프로젝트_개요.md`의 "명시적 제외" 목록 그대로 유지. Ocean-H 연동, 웹 DWG 열람, 자동 병합, DRM, SSO 등은 이번 범위에 없음.

## 7. 완료 기준 (Acceptance Criteria)

- [ ] 도면대장.xlsx의 10,827건이 시스템에 전량 적재됨
- [ ] Isometric을 제외한 도면 검색 시 2초 이내 목록 표시
- [ ] PDF 보유 도면은 브라우저에서 다운로드 없이 바로 열람됨
- [ ] 협력사에게 만료형 링크로 도면 1건 배포 → 다운로드 → 재업로드 → 검수 승인 → 신규 Rev 등록까지 전체 흐름이 끊김 없이 동작
- [ ] 동일 도면을 두 업체에게 배포 시 경고가 표시됨
- [ ] 관리자 화면에서 미입고 도면 목록이 정상 표시됨
