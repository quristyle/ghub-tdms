## 3. 확정된 기술 결정사항

| # | 결정 | 근거 |
|---|---|---|
| **D-1** | **열람은 PDF, 원본은 DWG 다운로드** | 웹 DWG 뷰어는 무료 방법이 없음. PDF는 이미 변환 완료되어 있어 즉시 가능 |
| **D-2** | **서버를 지금 사지 않는다** | 1단계는 CM PC 로컬(localhost)에서 혼자 구동. 동작 확인 후 사내 VM 신청 |
| **D-3** | **클라우드 배제** | P&ID·As-Built는 사업장 보안등급 자산. 사외 반출 시 보안 심의 리스크 |
| **D-4** | **도면번호 체계 변경 금지** | EPC가 부여한 체계를 그대로 고유 ID로 사용 |
| **D-5** | **분류정보는 폴더 경로에서 자동 추출** | 7,000장 수작업 입력 불필요 |
| **D-6** | **삭제 기능 없음** | 구본은 삭제가 아니라 Superseded(폐기) 처리 후 보관 |
| **D-7** | **DB에 `자료종류(doc_class)` 필드 확보** | 2차에 MDB 추가 시 재개발 방지 |
| **D-8** | **표준 기술 스택만 사용** | 유지관리 업체 이관 전제 |
| **D-9** | **P&ID는 현재 Revision 진행 중 → 시스템엔 "기능만" 만들고 실제 파일은 추후 업로드** | 완료를 기다리지 않고 개발 착수. `doc_type=P&ID` 데이터는 비어있는 상태로 두되, 등록·검색·열람 기능은 동일하게 지원 |
| **D-10** | **DWG-PDF 쌍 불일치(약 49%)는 지금 고치지 않는다** | 시스템 구성 후, 발견되는 대로 여력 있을 때 보완. MVP 개발의 선행조건이 아님 |

## 4. 기술 스택 (이관 가능성이 선정 기준)

| 계층 | 선정 | 이유 |
|---|---|---|
| 파일 저장 | **파일시스템 / NAS** (DB에 파일 넣지 않음. 경로+해시만 저장) | 이관 시 폴더째 복사 |
| DB | **PostgreSQL** | 업계 표준. 어느 업체든 인수 가능 |
| 백엔드 | **Python + FastAPI** | CM이 Python 경험 보유 |
| 프론트 | 단순 웹 (React 또는 순수 HTML) | |
| PDF 뷰어 | **PDF.js** | 무료, 완성도 높음 |
| 배포 | **Docker Compose** | 업체 인수인계 용이 |

## 6. 서버 단계 계획

| 단계 | 누가 쓰나 | PC 켜짐 필요 | 비고 |
|---|---|---|---|
| 1. 개발·PoC | CM 혼자 | 무관 | 브라우저로 `localhost` 접속. 서버 개념 없음 |
| 2. 팀 시연 | 팀원 3~5명 | 필요 | **사내 보안정책상 막힐 수 있음.** 안 되면 화면공유로 대체 |
| 3. 정식 운영 | 팀 + 협력사 | — | **사내 VM 할당 신청.** "구매"가 아닌 "자원 할당"이라 승인 문턱 낮음 |
