# TDMS 기술자료 관리 시스템 — 시스템 개요서 (외부 검수·보안진단·유지보수 견적용)

작성일 2026-10-12 / 작성: 설비기술팀 CM
이 문서는 코드를 처음 보는 IT업체가 규모와 구조를 빠르게 파악하도록 만든 것이다.
상세한 결정 배경은 같은 폴더의 `08_결정사항_이력.md`, 요구사항은 `06_요구사항_정의서.md`, DB 구조는 `DB구조_schema_only.sql`을 본다.

## 1. 시스템 목적과 현재 상태

- SK가스 G.Hub 사업장의 도면(TDB, DWG/PDF 약 1만 건)과 설비 데이터북(MDB) 자료를 관리하는 사내 웹 시스템.
- 정식 외주 과업이 보류된 동안 설비기술팀이 최소 기능만 자체 구축했고, 이후 전문 유지관리 업체에 인계하는 것을 전제로 표준 스택만 썼다.
- 현재: 개발 PC(localhost)가 코드 원본이고, Microsoft Azure Windows Server에 **시험 설치**되어 사내 인터넷 주소에서만 접속한다.
  실제 업무 자료는 아직 개발 PC에만 있다. 서버에는 코드와 시험 자료를 둔다.
- 사용자: 설비기술팀 CM 및 동료(사내 사용자). 협력사는 접근하지 않는다(파일은 CM이 이메일로 전달).

## 2. 기술 스택

| 계층 | 사용 기술 |
|---|---|
| 백엔드 | Python 3.13, FastAPI, SQLAlchemy 2, Alembic(DB 구조 이력), uvicorn |
| DB | PostgreSQL 16 (Windows 네이티브 설치. Docker 사용 안 함) |
| 프론트엔드 | 프레임워크 없는 순수 HTML / JavaScript / CSS (빌드 과정 없음) |
| PDF 뷰어 | PDF.js(오픈소스)를 **직접 수정해 사용** — `frontend/assets/pdfjs/` (아래 4절) |
| 파일 변환 | DWG→PDF: ODA File Converter(무료)+ezdxf+PyMuPDF / 오피스→PDF: LibreOffice |
| 파일 저장 | 서버 로컬 폴더(`STORAGE_ROOT`). DB에는 경로와 SHA256 해시만 저장 |
| 외부 연동 | **없음** — 외부 API·클라우드 서비스를 호출하지 않는다 |

사용 라이브러리의 정확한 버전은 `backend/requirements-lock.txt`에 있다(운영 의존성, 개발용 검사 도구 제외).
`backend/requirements.txt`는 버전을 고정하지 않은 목록이다.

## 3. 규모

| 항목 | 값 |
|---|---|
| 백엔드 파이썬 | 서버 코드(`app/`) 약 18,700줄, 일회성 작업 스크립트 포함 전체 약 27,800줄 (118개 파일) |
| API 엔드포인트 | 약 189개 (라우터 18개) |
| DB 테이블 | 22개 (`alembic_version` 포함), DB 변경 이력(마이그레이션) 29개 |
| 화면 | HTML 14개 (JS 20개, CSS 12개) — 우리가 만든 JS 약 16,200줄, CSS 약 5,200줄 |
| PDF 뷰어 수정분 | `frontend/assets/pdfjs/web/dms-*.js` 등 약 8,400줄 |
| 데이터 | 도면 10,827건 / 파일 약 16,400개 / 약 6.5GB (TDB), MDB 자료 약 1,200건 |

## 4. 폴더 구조

```
backend/
  app/            서버 본체
    main.py         앱 조립: 라우터 등록, 로그인 검사, 화면 파일 배포, 보안 장치 연결
    security.py     허용 주소 검사, 보안 머리글(CSP 등), 다른 사이트 쓰기 요청 차단
    auth.py         로그인·세션(서명 쿠키)·비밀번호 규칙·로그인 잠금
    permissions.py / permission_tree.py   그룹별 권한(화면·기능 트리)
    secret_values.py   .env의 비밀값 목록(백업·검사에서 제외용) 한 곳 관리
    storage.py      파일 저장 위치 규칙, sanitize_path_component(경로 이탈 방지)
    models.py       DB 테이블 정의
    routers/        기능별 API (documents, editor, mdb, mdb_editor, imports, distributions, backup, users, groups …)
    backup.py / preview_worker.py / original_preview.py   백업 묶음 생성, 원본(DWG·오피스) 미리보기 변환
  alembic/        DB 구조 변경 이력
  scripts/        과거 일회성 데이터 정리·이관 스크립트 (운영 코드 아님, 5절 끝 참고)
  security_check.py, bandit.yaml, bandit_baseline.json   자체 보안 자동 검사
frontend/         화면 (HTML/JS/CSS) — 서버가 그대로 내려준다
  assets/pdfjs/   PDF.js 수정본 (미리보기·도면 위 표시 그리기 기능)
docs/             요구사항·DB 설계·결정사항 이력·DB 구조(SQL)
.env.example      설정값 양식(실제 값은 포함하지 않음)
```

**PDF.js 수정본 주의**: 오픈소스 PDF.js 원본(`viewer.mjs`, `build/pdf.worker.mjs` 일부)을 직접 고쳤고,
그 위에 자체 기능(도형·스탬프·회전·복사·보관 등)을 `dms-*.js`로 얹었다. 보안진단 시 **오픈소스 원본 부분과
자체 작성 부분을 구분**해서 봐야 하며, PDF.js 버전 갱신 시 고쳐 둔 자리를 다시 적용해야 한다.

## 5. 보안 설계 요약 (현재 구현된 것)

| 영역 | 내용 |
|---|---|
| 인증 | 아이디·비밀번호 로그인, 서명 쿠키 세션(`SECRET_KEY` 필수, 없으면 서버가 켜지지 않음). 5회 연속 실패 시 15분 잠금, 실패는 접속 주소와 함께 시스템 로그에 기록 |
| 비밀번호 | 영문+숫자 8자 이상. 해시 저장. 계정 생성·초기화 시 초기 비밀번호는 `ghub`+아이디 규칙이고, 첫 로그인 때 변경 화면이 먼저 열린다(미루기 가능 — 미루면 다음 로그인 때 다시 열림) |
| 접근 제한 | `ALLOWED_CLIENT_IPS`에 없는 주소는 로그인 화면도 못 본다(403). Azure 방화벽에도 같은 주소만 허용 |
| 권한 | 관리자(ADMIN)와 일반(VIEWER)+그룹 권한 트리. 화면마다 "페이지 접속" 권한이 있고, API에도 서버에서 권한을 검사한다 |
| 웹 보안 | 보안 머리글(CSP 등), `/docs`·`/openapi.json` 비활성, 다른 사이트에서 온 쓰기 요청 차단, 화면 출력 시 HTML 이스케이프 |
| 입력·파일 | ORM 사용(문자열 이어붙인 SQL 금지), 사람이 적은 이름이 파일 경로가 될 때 경로 이탈 방지, Zip 업로드 경로 검사, 엑셀 내보내기 수식 무력화 |
| 외부 프로그램 | `subprocess`는 목록 인자만, `shell=True` 미사용, 윈도우 도구는 전체 경로로 호출 |
| 비밀값 | `.env`에만 보관. 코드·로그·백업 묶음에 들어가지 않도록 `secret_values.py`로 검사·제외 |
| 감사 | 로그인·반출·업로드·승인·삭제 보관함 비우기·백업 등 주요 동작을 시스템 로그(`audit_log`)에 기록 |
| 삭제 정책 | 자료를 지우는 기능이 없다(보관함·폐기 보관함으로 옮기고 복구 가능). 예외 몇 곳만 완전 삭제 허용(`08_결정사항_이력.md` 참조) |
| 자체 자동 검사 | `backend/security_check.py` — 비밀값 노출, bandit(파이썬 보안), 로그인 적용 여부, 엑셀 수식 막기, 화면 코드 위험 패턴을 한 번에 검사. 최근 결과(`보안검사_결과_20261012.txt`: 새 경고 0건)를 패키지에 포함했다 |

알려 두는 사항(진단 시 참고):
- 초기 비밀번호 규칙(`ghub`+아이디)은 관리 편의를 위한 CM 결정이며, 첫 로그인 변경 화면과 미루기 기능이 함께 있다.
  보안진단에서 지적될 가능성이 있는 항목이다.
- bandit 기준표(`bandit_baseline.json`)의 기존 경고 11건은 모두 확인을 마친 오탐(비밀번호처럼 보이는 문구 등)이다.
- `backend/scripts/`는 과거 데이터 정리용 일회성 코드라 운영에 쓰이지 않는다. 유지보수 견적에서는 제외해도 된다
  (단, `bulk_import.py`·`set_password.py` 등 일부는 초기 적재·관리용으로 유지될 수 있다).

## 6. 실행·배포 환경

- 실행: `backend\run_server.py` (uvicorn). 설정은 `.env`(양식: `.env.example`) — DB 접속, 파일 저장 위치, 서명키, 허용 주소, 서버 주소·포트, HTTPS 인증서 경로, 변환 도구 경로, 백업 위치.
- 서버(시험): Azure Windows Server, 사내 인터넷 주소에서만 접속, HTTPS 적용.
- 별도 설치가 필요한 프로그램: PostgreSQL 16, Python 3.13, ODA File Converter(DWG 변환), LibreOffice(오피스 변환), (백업용) `pg_dump`.
- 배포 방식: 개발 PC에서 고친 코드를 묶어 서버에 복사(zip+scp)하고, DB 구조 변경은 Alembic으로 적용한다. 서버에서 코드를 직접 고치지 않는다.
- 백업: 화면(백업 관리)에서 DB·자료·코드·화면 묶음을 만들어 서버 밖으로 내려받는다. 되살리기는 묶음 안 안내 파일대로 사람이 수행한다.

## 7. 외부 업체에 요청하는 범위(예시)

1. 소스코드 검수 및 보안진단(웹 취약점, 인증·권한, 파일 업로드·경로, 설정, 의존 라이브러리 취약점)
2. 서버 구성 진단(Azure 네트워크, HTTPS, 방화벽, OS 보안 설정)
3. 정식 도입 시 유지보수 견적 — 위 3절 규모와 4절 구조를 기준으로 산정

## 8. 이 패키지에 없는 것(의도적으로 제외)

실제 비밀번호·서명키(`.env`), 업무 자료 파일, 실제 데이터가 담긴 DB, 백업 묶음, 로그, 가상환경(`venv`),
서버 접속 정보, 소스 버전 이력(`.git`). 진단용 접속이 필요하면 별도로 시험 계정을 발급한다.
