# 01. 아키텍처

## 1. 전체 구성

```
                        ┌─ nginx (HTTP/2, TLS, brotli) ───────────────────┐
  브라우저 ──────────── │  /            정적 (immutable, 1년 캐시)          │
                        │  /api/        → unix:/run/tdms/api.sock          │
                        │  /_blob/      internal → sendfile 직송            │
                        └──────────────────────────────────────────────────┘
                                   │                        │
                   ┌───────────────┴──────┐      ┌──────────┴───────────┐
                   │ tdms-api.service     │      │ /srv/tdms/blobs/     │
                   │ Node 22 + Fastify 5  │      │ ab/cd/<sha256>       │
                   │ 상주 ~150MB          │      │ (불변·중복제거)       │
                   └───────────┬──────────┘      └──────────────────────┘
                               │ unix socket
                   ┌───────────┴──────────────────────────────┐
                   │ PostgreSQL 16  (jit=off, 로컬 소켓)       │
                   │  · 데이터   · 세션   · 작업큐(SKIP LOCKED)│
                   └───────────┬──────────────────────────────┘
                               │ LISTEN/NOTIFY
                   ┌───────────┴──────────┐
                   │ tdms-worker@N        │  DWG·오피스 변환 / Zip / 엑셀 /
                   │ Python 3.12          │  백업 / 대량반입  (샌드박스 격리)
                   └──────────────────────┘
```

**프로세스 3종, 미들웨어 0개.** Redis·메시지브로커·컨테이너 오케스트레이터를 쓰지 않는다.
절약이 아니라 성능 선택이다 — 네트워크 홉이 없고(유닉스 소켓), 캐시 일관성 문제가 없으며,
장애 지점이 3개뿐이다.

## 2. 기술 선택과 근거

| 선택 | 대안 | 근거 |
|---|---|---|
| **Fastify 5** | Express, NestJS | 응답 직렬화를 스키마에서 미리 컴파일(`fast-json-stringify`). 200행 목록 JSON 생성이 `JSON.stringify` 대비 2~3배 빠르다. 플러그인 캡슐화가 모듈 경계를 강제한다. NestJS는 DI 레이어만큼 느리고 무겁다. |
| **`pg` 직접 + SQL** | Prisma, TypeORM, Drizzle | 이 앱의 성능은 복잡한 조회 쿼리 약 10개에서 결정된다. `LATERAL`·`ltree`·`trgm`을 쓰려면 SQL을 직접 써야 한다. Prisma는 별도 쿼리엔진 바이너리가 상주한다. |
| **유닉스 도메인 소켓** | TCP 127.0.0.1 | nginx↔API, API↔PG 모두 소켓. TCP 스택·포트 고갈·TIME_WAIT가 없다. |
| **Python 워커 유지** | TS로 통일 | `ezdxf`·`PyMuPDF`·LibreOffice에 Node 생태계 동등 대체재가 없다. TS로 옮기면 품질이 떨어지고 공수만 는다. |
| **컴포넌트 프레임워크 미사용** | PrimeVue, Element Plus | 기존 화면을 픽셀 단위로 재현해야 하는데 키트를 쓰면 CSS 오버라이드가 쌓이고, 번들이 커지고, 메이저 버전업에 끌려다닌다. |
| **PostgreSQL 작업큐** | Redis, RabbitMQ | 변환 작업은 하루 수십~수백 건. 미들웨어를 하나 늘려도 빨라지지 않는다. `SKIP LOCKED`로 충분하다. |

## 3. 저장소 구조

```
/srv/tdms/
  blobs/        ab/cd/<sha256 hex>      불변. 내용으로 주소를 삼는다. 중복 자동 제거
  mirror/최신/  원본 공유폴더와 같은 모양    야간 하드링크 재구성. 디스크 추가 사용 없음
  tmp/          업로드·변환 작업 공간
  web/          Vue 빌드 산출물
  app/          API 빌드 산출물
  worker/       Python 워커 + venv
```

### content-addressed 를 택한 이유

| 작업 | 기존 (경로 기반) | 신규 (blob 기반) |
|---|---|---|
| 폴더 이름 변경 (하위 500건) | 문자열 UPDATE 500 + 디스크 이동 500 | row 1개 UPDATE |
| 리비전 승인 1건 | 디스크 rename 2~3회 + UPDATE | row UPDATE만 |
| 자료 이동 | 디스크 이동 + UPDATE | row UPDATE만 |
| 중복 파일 | 그대로 중복 저장 | 자동 제거 |
| 중간 실패 시 | DB·디스크 불일치 | 트랜잭션 롤백으로 끝 |

### `최신` 폴더 요구의 충족

기존 CM 요구: *"시스템을 그만 쓸 때 `최신` 폴더만 가져가면 그대로 쓸 수 있어야 한다."*

→ 야간 배치가 blob에서 **하드링크**로 `mirror/최신/` 트리를 재구성한다.
디스크를 추가로 쓰지 않고, 이름 규칙이 바뀌어도 다음 날 자동 반영된다.
즉시 필요하면 화면에서 "내보내기"로 원하는 범위를 Zip으로 뽑는다.

## 4. 요청 경로별 처리

### 일반 API
```
브라우저 → nginx(/api/) → unix socket → Fastify
  → 세션 조회(캐시) → 권한 검사(캐시) → 핸들러 → SQL(prepared) → 직렬화(컴파일됨) → 응답
```

### 파일 다운로드 — 앱이 바이트를 만지지 않는다
```
브라우저 → nginx(/api/files/:id/download) → Fastify
  → 권한 검사 + 감사 기록 → X-Accel-Redirect 헤더만 반환
  → nginx 가 /_blob/ab/cd/<sha> 를 커널 sendfile 로 직송
```
6.5GB Zip 반출 중에도 Node 이벤트 루프는 비어 있다.

### 장시간 작업
```
브라우저 → POST /api/.../export → jobs INSERT → 즉시 202 {jobId}
                                      ↓ NOTIFY
                           Python 워커가 SKIP LOCKED 로 획득
                                      ↓ 진행률 UPDATE
브라우저 ← SSE /api/jobs/:id/stream ← Fastify 가 LISTEN 으로 수신
                                      ↓ 완료
브라우저 → GET /api/jobs/:id/download → X-Accel-Redirect
```

## 5. 캐시 전략

프로세스 내 LRU만 사용한다. 무효화는 PostgreSQL `NOTIFY`가 방송한다.

| 대상 | TTL | 무효화 채널 |
|---|---|---|
| 사용자별 권한 리프 집합 | 60초 | `cache_perm` |
| 폴더 트리 뼈대 (TDB/MDB) | 영구 | `cache_tree` |
| 타입 목록 (설비유형·자료유형·업체·공사) | 영구 | `cache_types` |

기존 시스템은 **모든 요청마다 권한을 DB에서 조회**했다(`permissions.py`).
이 구조 덕분에 나중에 API를 2~4 프로세스로 늘려도 캐시 일관성이 유지된다.

## 6. 보안 경계

| 영역 | 처리 위치 | 기존 지적 해소 |
|---|---|---|
| 접근 IP 허용 | **nginx** (`allow`/`deny` + `real_ip`) | S-08 프록시 뒤 무력화 |
| 업로드 크기 | nginx `client_max_body_size` + 앱 매직바이트 검증 | 업로드 무제한 |
| 세션 | **DB 세션 테이블** (서명 쿠키 폐기) | S-03 서버측 무효화 불가 |
| 권한 | 라우트 선언형 + 기동 시 전수 검증 | S-06 트리에 없으면 개방 |
| 감사 | 파일 접근이 단일 게이트를 통과 → 누락 불가 | S-07 인라인 열람 미기록 |
| 비밀값 | systemd `LoadCredential=` | 평문 `.env` |
| 변환 워커 | 전용 계정 + `PrivateNetwork` + `ProtectSystem=strict` | 비신뢰 입력 파서 격리 |
| 감사로그 불변 | `REVOKE DELETE, UPDATE ... FROM tdms_app` | 감사로그 보존 |

## 7. 저장소 레이아웃 (소스)

```
ghub-tdms/
├─ docs/                설계문서 (이 폴더)
├─ packages/
│  ├─ contracts/        Zod 스키마 1벌 → 검증 + OpenAPI + FE 타입
│  ├─ api/              Fastify. 모듈 18개 (기존 라우터와 1:1)
│  ├─ worker/           Python 3.12
│  └─ web/              Vue 3.5 + Vite
├─ db/
│  ├─ migrations/       번호순 SQL
│  └─ seed/             초기 데이터
├─ deploy/              nginx.conf, *.service, Ansible
└─ baseline/            기존 시스템 OpenAPI 스냅샷, 화면 체크리스트 (동등성 기준선)
```

`packages/api/src/modules/` 의 이름을 기존 라우터와 1:1로 맞춘다 —
누락 여부를 폴더 목록만 봐도 알 수 있게 하기 위해서다.
